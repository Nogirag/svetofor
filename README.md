# Светофор

Страница-светофор с обратным отсчётом, московским временем алгоритма (GMT+3), ночным режимом и сбором отметок наблюдателей в общую таблицу на сервере.

## Что делает

- Горит один из трёх сигналов сверху вниз: красный → жёлтый → зелёный.
- Дневной цикл по умолчанию: **красный 120 с**, **жёлтый 3 с**, **зелёный 25 с**.
- Часы алгоритма — **московские (GMT+3)**, на любом телефоне. Фаза привязана к абсолютному времени и к якорю «красный включается в ЧЧ:ММ:СС по МСК», поэтому все устройства, открывшие один адрес, показывают один и тот же цвет, даже если у них разная дата в настройках или другой часовой пояс.
- Отметка цвета не нажимается случайно: на экране одна кнопка «Отметить, какой цвет вы видите», а «Красный» и «Зелёный» открываются меню снизу и закрываются сами сразу после отметки.
- Отметка уходит на сервер, локальная копия остаётся в браузере.
- ⚙ — длительности цикла и момент включения красного. Настройки одного устройства отключены: цикл у всех один, он лежит в файле на сервере, а из браузера его правит только тот, кто ввёл пароль владельца. Пароль спрашивается прямо в панели, отдельного окна входа нет. Там же — «Настроить по нажатиям».
- ⏱ — калибровка сразу, без захода в настройки: пять светофоров на дневной цикл и пять на ночной, нажимаете лампу — рядом пишется время по МСК, и цикл считается сам. Без пароля пятёрка открывается для просмотра; пароль вводится тут же, строкой сверху, и после него нажатия начинают считаться.
- 📊 — статистика рассогласований и предложение по подстройке красного; выгрузка общей таблицы — тоже только по паролю.
- 📲 — инструкция по добавлению на главный экран для iOS и Android.

## Запуск локально

```bash
node tools/set-owner-password.mjs   # один раз: новый пароль владельца, печатается в консоль
node server/api.mjs                 # http://localhost:8080 — страница и приёмник вместе
```

Скрипт пишет два свёртка — `server/config/admin.password` и `public/js/owner-key.js` — и ни один из них не попадает в git. Свой пароль можно задать сразу: `--password '…'`.

Для отладки без сервера: `python -m http.server 8081 --directory public` — на **другом** порту, не на 8080. Страница работает и так: отметки копятся в локальной очереди, цикл берётся из значений по умолчанию в коде, а ⚙ разблокируется паролем, но сохранять цикл некуда — серверного конфига нет.

Если ⚙ не открывается, порядок проверок такой: `curl http://localhost:8080/api/health` должен ответить `{"ok":true,…,"ownerPassword":"on"}`. Не отвечает — Node-сервер не запущен (на Windows `node` часто не в `PATH`, тогда запускайте полным путём к `node.exe`). Отвечает, но `ownerPassword` — `off`, значит нет секрета. А если по этому адресу сидит статик-сервер (та же команда `python -m http.server`, только на 8080), страница продолжит открываться — `sw.js` держит кэш оболочки, — но `/api/*` будет отвечать 404, и панель верно скажет «на этом адресе нет серверного API». Проверяйте, какой процесс занял порт: `netstat -ano | findstr :8080`.

Переменные окружения сервера: `PORT` (8080), `DATA_DIR` (`server/data/observations`), `CONFIG_FILE` (`server/config/settings.json`), `ADMIN_PASSWORD` / `ADMIN_PASSWORD_FILE` (пароль владельца), `STATIC_DIR` (`public`), `FEEDBACK_KEY` (ключ приёмника).

## Отметки: как собираются и где хранятся

Одна отметка = одна строка таблицы. Поля: время, id устройства, профиль (день/ночь), что горело на экране, что ответил наблюдатель, момент внутри фазы, остаток до переключения, длительность фазы, поправка часов и `shift_ms` — уже посчитанное смещение зелёного.

Путь отметки: тап по кнопке в меню → `record` в [public/js/feedback.js](public/js/feedback.js) → `POST /api/observations` на сервер → дописывание строки в `server/data/observations/YYYY-MM-DD.jsonl`. Дни в имени файла — **московские**: у файла и у цикла одна и та же полночь. Параллельно копия лежит в `localStorage` браузера (`trafficlight.observations.v1`, максимум 5000 строк) — она нужна, чтобы панель работала офлайн.

Если сервер недоступен, строка попадает в очередь `trafficlight.queue.v1` (максимум 300) и отправляется при следующем открытии страницы, при событии `online` и раз в пять минут. Дубликаты на сервере возможны при повторной отправке — у строки нет идемпотентного ключа, при выгрузке дедуплицируйте по `ts + device`.

Эндпоинты:

| метод | путь | доступ | что возвращает |
|---|---|---|---|
| POST | `/api/observations` | открыт (опционально `x-feedback-key`) | принимает одну отметку, 201 при успехе |
| GET | `/api/config` | открыт | расписание из `server/config/settings.json` — его страница показывает у всех |
| POST | `/api/config` | `x-admin-password` | записывает новый цикл в `settings.json` |
| GET | `/api/admin/check` | `x-admin-password` | 200 «пароль верный» / 401 «не верный» / 503 «пароля на сервере нет» |
| GET | `/api/summary?days=7` | открыт | сводка по всем устройствам: строки, устройства, медиана и P90 смещения. Строк с id устройств там нет |
| GET | `/api/export.csv?days=90` | `x-admin-password` | вся таблица одним CSV (`;`, с BOM) — датасет для будущего обучения |
| GET | `/api/health` | открыт | `{ ok, timezone, receiverKey, ownerPassword }` — включены ли секреты, без самих путей и значений |

Сервер проверяет тело (не больше 8 КБ), значения полей (цвет, профиль, диапазоны времени), обрезает id устройства, ограничивает частоту (120 запросов в минуту на адрес, для закрытых разделов — 20) и не пускает за пределы папки с данными. Пароль сравнивается через `timingSafeEqual` (при разной длине — через свёртки SHA-256), чтобы его нельзя было подобрать по времени ответа. Если задан `FEEDBACK_KEY`, отметки принимаются только с заголовком `x-feedback-key`; его нужно вписать в `<meta name="feedback-key">` в [public/index.html](public/index.html).

## Ручная подстройка цикла

Расписание живёт в `server/config/settings.json` — этот файл правят по FTP, и он источник истины для всех устройств. Страница читает его при загрузке и перечитывает каждые 30 секунд, поэтому правка файла доходит до всех телефонов сама: заходить в каждый браузер не нужно. Формат файла и таблицы диапазонов — в [server/config/README.md](server/config/README.md); значение вне диапазона, битое время или неизвестный режим молча заменяется разумным, а невалидный JSON не роняет раздачу (сервер продолжает отдавать последнюю исправную версию).

Отдельных настроек на устройстве больше нет: ни переопределения цикла «для одного телефона», ни локального режима для хостинга без API. В `localStorage` остаются только поправка часов (`trafficlight.clock.v1`) и последний полученный цикл (`trafficlight.schedule.cache.v1`) — кэш, чтобы страница без сети горела по правильному расписанию. Оба сервер перезаписывает сам.

Из браузера тот же файл правится по паролю владельца. Порядок:

1. Тап по ⚙ (или ⏱ для калибровки) — панель открывается сразу, первой строкой стоит поле пароля.
2. «Открыть» или Enter → пароль сверяется прямо в странице, без запроса к серверу: работает на любом адресе, в том числе по `http://` в локальной сети и на статик-хостинге. В странице лежит только свёрток (`public/js/owner-key.js`, две FNV-1a-суммы), сам пароль — у владельца; `server/config/admin.password` хранит его `sha256:<hex>` для серверных проверок. Оба файла создаёт `node tools/set-owner-password.mjs` и оба не попадают в git.
3. Верный пароль сохраняется в `localStorage` этого браузера (`trafficlight.owner.v1`) и только там: на других телефонах и компьютерах панель по-прежнему просит пароль.
4. Правка интервалов → «Сохранить на сервере» пишет `settings.json` через `POST /api/config` — цикл меняется сразу у всех, а на этом телефоне следующее сохранение не требует пароля (тап ⚙ сразу открывает форму с доступными полями).
5. Кнопка «Закрыть доступ в этом браузере» убирает пароль (например, на чужом устройстве).

Отдельного окна входа нет: пока пароль не введён, настройки открыты только для чтения, а калибровка показывает пятёрку светофоров без записи нажатий — после пароля она сразу начинает считать.

Заголовки HTTP живут в Latin-1 — это касается только запросов на сервер (сохранение, выгрузка): пароль с кириллицей или пробелом туда не уйдёт. Входу в панель это не мешает — свёрток в странице понимает любые символы.

Если пароля на сервере нет (`admin.password` не создан, `ADMIN_PASSWORD` не задан), запись конфига и выгрузка закрыты (503): остаётся FTP. Если серверного API нет вовсе (статик-хостинг, `file://`), панель разблокируется паролем, но сохранить цикл некуда — она так и скажет; страница горит по расписанию из кода, и это тот случай, когда цикл нужно раздавать сервером. Сверка пароля при сохранении идёт и на сервере: если свёртки в странице и в `admin.password` разошлись, запись не пройдёт, и панель снова закроется.

Без `public/js/owner-key.js` (свежий клон репозитория) вход не сломан: панель сверяет пароль на сервере, как до появления локального свёртка. Чтобы вход работал и по `http://` без сервера, создайте файл — `node tools/set-owner-password.mjs`. Смена пароля — тот же скрипт: он перезаписывает оба свёртка и один раз печатает новый пароль.

Что видно в панели настроек и статистики: откуда берётся расписание, открыт ли доступ и открыта ли выгрузка. Без доступа форма показывается только на чтение — поля выключены, «Сохранить» нет.

Что можно настроить:

1. **Дневной цикл** — красный, жёлтый, зелёный в секундах (1–3600, жёлтый ограничен 60 с).
2. **Красный включается в, МСК** — якорь цикла, «ЧЧ:ММ:СС». Цикл непрерывен: жёлтый идёт через красный, зелёный — через красный и жёлтый, следующий красный — через всю длину цикла. Без якоря дневной цикл стартует с красного в московскую полночь, а если включён ночной режим — в момент окончания ночного окна. Ночной цикл стартует с красного в начало окна, и у него свой якорь («Красный включается в» под ночными длительностями, активен только в режиме «Отдельный цикл»). Поэтому переключение день/ночь всегда начинается с новой фазы, а не с середины чужого цикла, и окно может переходить через полночь (23:00–06:00 понимается как одно окно).
3. **Ночной режим** — чекбокс, время начала и окончания (по МСК), режим:
   - **Мигающий жёлтый** — отсчёт гаснет, жёлтая лампа мигает раз в секунду, кнопки продолжают писать отметки, но на цикл не влияют;
   - **Отдельный цикл** — свои длительности красного/жёлтого/зелёного на ночь.
4. **Исходные 120 / 3 / 25** — сброс дневного и ночного цикла, их якорей и выключение ночного режима.

Якорь определён с точностью до длины цикла: при цикле 90 с «00:00:37» и «14:32:07» — один и тот же сигнал. Страница и `derive` всегда показывают ту реплику, что ближе к последнему наблюдению, чтобы её было удобно сверять с часами.

### Настройка по нажатиям у настоящего светофора

Стоя у светофора дольше, чем длится цикл, можно не считать секунды вручную: ⏱ в верхней панели — сразу калибровка, ⚙ — настройки. Обе панели открываются без пароля, но без него они только для чтения: поле пароля стоит первой строкой в самой панели, и после ввода настройки становятся доступны, а калибровка сразу начинает считать нажатия. Отдельного окна входа больше нет; пароль остаётся в браузере, так что на этом устройстве он спрашивается один раз.

В панели пять светофоров — по одному на цикл, и переключатель **Дневной / Ночной**. У каждого профиля своя пятёрка и свои метки, поэтому за одну сессию можно снять оба цикла и сохранить их вместе.

1. Нажимайте ту лампу, которая включилась: под ней сразу появляется время нажатия по МСК. Подсвечена лампа, которую страница ждёт следующей — по ней видно, куда попадёт нажатие.
2. Один светофор = один цикл: красный, жёлтый, зелёный. После пятого зелёного один лишний красный замыкает пятый цикл — без него зелёный последнего цикла не измерен (его длительность — это время до следующего красного).
3. Выше ламп идёт строка «по циклам»: по каждому светофору красный / жёлтый / зелёный в секундах, то есть сырые измерения фаз.
4. Меню можно свернуть (✕ или тап по фону) и нажимать прямо по большому сигналу на экране — он засчитает тот цвет, который страница ждёт следующим. Во время настройки экран повторяет нажатия, а не старое расписание; сверху висит плашка «Настройка: дневной цикл, светофор 2 из 5, ждём жёлтый · 4 метки из 15».
5. «Отменить последнее» убирает промах в текущем профиле, «Начать заново» — метки обоих, «Прервать настройку» — выходит из режима, ничего не сохраняя.
6. «Закончить и сохранить» считает готовые профили и пишет их одним `POST /api/config`: дневной и ночной циклы вместе, ночные окна и якоря не трогаются.

Что считает [public/js/schedule.js](public/js/schedule.js) (`derive`): из меток собираются группы красный→жёлтый→зелёный→красный (лишняя или перепутанная метка просто не сходится в этой точке и пропускается), длительности берутся медианой по всем группам, якорь — круговой медианой моментов красного внутри длины цикла. В превью видно результат, число полных циклов, длину цикла и разброс «±N с» между включениями красного — по нему понятно, стоит ли дожимать ещё цикл. Пять светофоров дают пять измерений на цвет: медиана уже не сдвинется от одного промаха. Метки живут только в памяти страницы: они никуда не сохраняются, а сервер получает уже готовый цикл.

Настройка не обходит пароль: кнопка видна только разблокированному владельцу, а сохранение идёт через тот же `POST /api/config` с лимитом 20 запросов в минуту.


### Почему часы не зависят от телефона

`public/js/schedule.js` и сервер оперируют обычным epoch, а «стенные» минуты считают со сдвигом `+3 часа` (`TZ_OFFSET_MS`), без локального часового пояса и без `Date`-геттеров: Москва на летнее время не переводится, так что смещение постоянно. Точку отсчёта фазы даёт `wallMidnight` — эпоха московской полуночи.

Часы самого устройства всё же врут, а неверное время — это «не тот» цвет. Поэтому страница раз в 10 минут и при возвращении на вкладку берёт заголовок `Date` ответа сервера и хранит разницу как поправку; в подвале она подписана «часы алгоритма: GMT+3 (МСК), правка −0,8 с». Отметки пишутся уже скорректированным временем, поэтому статистика не разъезжается с расписанием.

## Как алгоритм предлагает скорректировать цикл

Ответов два, поэтому весь сигнал сводится к одному моменту — когда зелёный включается на самом деле. `shift_ms` считается в момент нажатия:

- «Зелёный» при красном или жёлтом → реальность опережает расписание на время до ближайшего зелёного (при красном добавляется ещё и весь жёлтый).
- «Красный» при зелёном → реальность отстаёт на время, которое зелёный уже горит по расписанию.

Берётся медиана смещений: она устойчива к одиночным промахам и к нажатию «на всякий случай». Предлагаемый красный = текущий минус медиана, в пределах 5–3600 с; предлагаемый якорь = текущий минус та же медиана в секундах, с остатком по суточному кругу. Предложение появляется после `MIN_SAMPLES` (3) несовпавших отметок.

Источник смещения — **сводка сервера**, если она доступна: тогда алгоритм учитывает опыт всех устройств, а не одного телефона. Без сервера считается по локальным отметкам. В панели указано, что именно использовалось. Совпавшие отметки в расчёт не идут, но видны как «Отметки совпали» — по ним видно, что модель держится.

Из той же медианы растут два взаимоисключающих предложения, и выбирает между ними человек:

- **«Красный (день): A с → B с»** — длительности не совпадают: красный короче (или длиннее) на медианное смещение. «Применить» меняет только дневной красный и уходит на сервер (ночной цикл остаётся ручным).
- **«Старт красного (день): ЧЧ:ММ:СС → ЧЧ:ММ:СС»** — длительности верны, а мимо стоит лишь фаза: якорь сдвигается на медиану (с точностью до длины цикла). «Сдвинуть» меняет только `phaseStart` дневного цикла.

Оба видит только тот, кто разблокировал доступ паролем; остальные читают «нужен пароль владельца». Если смещение меньше секунды, второго предложения нет — двигать якорь некуда.

## Тесты входа

Закрытые разделы (запись расписания, выгрузка таблицы) проверяются скриптом [tests/owner-login.mjs](tests/owner-login.mjs) — без внешних зависимостей, на том же Node 18+:

```bash
TL_ADMIN_PASSWORD='пароль владельца' node tests/owner-login.mjs
node tests/owner-login.mjs --password 'пароль владельца'     # то же самое
node tests/owner-login.mjs                                   # без пароля: часть проверок
node tests/owner-login.mjs --base http://localhost:8080      # по уже запущенному серверу
```

Открытый пароль в репозитории не лежит, поэтому тестам его передают снаружи; первым делом скрипт сверяет его со свёртком в `admin.password` (проверка `P00`) и честно пропускает вход, если пароль не передан. По умолчанию тест поднимает свои инстансы сервера на свободных портах и гасит их, поэтому лимиты и «пароля нет вовсе» проверяются независимо друг от друга.

| набор | что покрывает |
|---|---|
| `A` | верный пароль и одиннадцать неверных (последний символ, пустой заголовок, заголовка нет, свёрток вместо пароля, хеш без префикса, другой регистр, обрезанный, длиннее на символ, пробел внутри), пробелы по краям их срезает HTTP-слой, `POST /api/config` и `GET /api/export.csv` без пароля / с неверным / с верным, публичное `GET /api/config`, итог: файл `settings.json` побайтно тот же |
| `B` | свёрток в переменных окружения верхним регистром (`SHA256:<HEX>`) |
| `D` | пароля на сервере нет: `health` показывает `ownerPassword: off`, закрытые разделы отвечают 503, расписание при этом читается |
| `E` | перебор: 21-е обращение к закрытому разделу за минуту — 429, и верный пароль в этом окне тоже 429; публичное чтение лимит не задевает |
| `C` | клиентская половина ([public/js/feedback.js](public/js/feedback.js) в песочнице `node:vm`): кириллица и пробел не отправляются в сеть вовсе, коды 200/401/403/503/429/500/404/405 превращаются в `ok/wrong/wrong/missing/slow/offline/noapi/noapi`, запрос, который не дошёл вовсе, — тоже `offline`, разблокировка хранит пароль в `localStorage`, отозванный пароль клиент замечает и закрывает доступ; вход без сервера — свёрток принимает верный пароль и отвергает варианты; без `owner-key.js` локальный вход выключен, а сохранённая запись не стирается; `owner-key.js` совпадает с переданным паролем |

Запуск с `--base` не трогает лимиты и состояние сервера: проверки «перебор закрыт 429» и «пароля на сервере нет» в этом режиме не запускаются, а запись конфига отправляет то же содержимое `settings.json`, что уже лежит, — файл остаётся побайтно тем же (это и фиксирует проверка `A17`). Полный прогон — 51 проверка, `exit 0`; при любом провале `exit 1`, так что скрипт можно ставить в CI.

## Публикация

Нужен HTTPS: без защищённого соединения браузер не даёт ни service worker, ни установку на главный экран.

**Вариант 1 — Node на VPS или в PaaS.** Один процесс раздаёт страницу, принимает отметки и отдаёт конфиг:

```bash
cd светофор
FEEDBACK_KEY=секрет ADMIN_PASSWORD=секрет-для-настроек PORT=8080 node server/api.mjs
```

Пароль владельца задаётся скриптом `node tools/set-owner-password.mjs` (или переменной `ADMIN_PASSWORD`): он пишет свёрток в `server/config/admin.password` и второй, страничный свёрток в `public/js/owner-key.js` — оба в `.gitignore`. На сервер и на хостинг эти два файла выкладываются отдельно от репозитория, и держать их нужно в секрете. Файл сервера хранит не открытый пароль, а его свёрток `sha256:<64 hex>`; сервер видит префикс и сравнивает хеш от того, что ввёл человек. Подробности — в [server/config/README.md](server/config/README.md). Если секрет не задан ничем, выгрузка и запись конфига закрыты (503), а расписание правится только файлом; страничный свёрток при этом всё равно даёт открыть панель.

Данные — в `server/data/observations`, папку стоит держать на постоянном диске (в контейнере — на volume). За nginx put через `pm2` или `systemd`, проксируя `/api/` на Node и отдавая статику из `public/`. Наружу из `server/` ничего отдавать нельзя: там и таблица отметок, и `admin.password`.

**Вариант 2 — статический хостинг без Node.** Выложить содержимое `public/` (вместе с `public/js/owner-key.js`, если нужен вход по паролю — он не в git и заливается отдельно). Страница, отсчёт, ночной режим и локальная статистика работают; отметки не уходят на сервер и копятся в очереди, а ⚙ открывается только для чтения: серверного конфига нет, сохранять некуда, отдельной настройки на телефоне больше не предусмотрено. Чтобы включить приёмник и правку цикла, вынести `/api/` на отдельный сервис с теми же эндпоинтами из таблицы.

MIME-типы, если хостинг задаёт их сам:

| расширение | тип |
|---|---|
| `.webmanifest` | `application/manifest+json` |
| `.js` | `text/javascript` |
| `.svg` | `image/svg+xml` |

После правки статики поднимайте версию в `CACHE` в [public/sw.js](public/sw.js), иначе браузеры будут держать старую оболочку.

## Известные ограничения

- Форма настроек всегда отправляет якорь явно. Пока поле не трогали, его значение — производное от ночного окна (конец окна для дня, начало для ночи), но после первого сохранения оно фиксируется: перенести ночное окно и не сдвинуть «Красный включается в» уже нельзя, правьте оба поля.
- Метки настройки по нажатиям живут только в памяти открытой страницы: перезагрузка или закрытие вкладки во время настройки теряют их (сохранённого цикла это не касается).
- Пароль владельца — единственная защита закрытых разделов: он хранится в `localStorage` разблокированного браузера, а не в аккаунте. Тот, кто прочитает файл на сервере, получит свёрток, а не пароль — но тот, кто доберётся до `localStorage` разблокированного телефона, увидит пароль в открытом виде и сможет им пользоваться; пароли наблюдателей здесь не нужны, но и полноценной учётной записи нет.
- Вход проверяется свёртком в самой странице (`public/js/owner-key.js`), поэтому скачавший страницу получит этот свёрток. В git он не попадает, но на сервере лежит рядом со страницей: длинный случайный пароль по нему не подобрать, короткий — можно, поэтому `tools/set-owner-password.mjs` по умолчанию делает 192-битный.
- Передача пароля идёт по HTTP-заголовку, поэтому без HTTPS он читается тем, кто смотрит трафик. HTTPS обязателен и для установки на главный экран.
- `/api/config` открыт на чтение: расписание видно всем — иначе страница не смогла бы его показывать. Секрета в этом файле нет, пароли в `server/` лежат отдельно и наружу не отдаются.
- Сводка `/api/summary` открыта и содержит только количества и медиану, без id устройств и без отдельных отметок.
- У отметки нет идемпотентного ключа, повторная отправка одной и той же строки возможна.
- Приватный режим Safari не сохраняет `localStorage` между запусками: локальная копия, очередь и разблокировка паролем живут до закрытия вкладки, панель об этом предупреждает.
- iOS не умеет добавлять на главный экран по кнопке — только через меню «Поделиться», поэтому там лежит инструкция, а не установщик.
