# Светофор

Страница-светофор с обратным отсчётом, московским временем алгоритма (GMT+3), ночным режимом и сбором отметок наблюдателей в общую таблицу на сервере.

## Что делает

- Горит один из трёх сигналов сверху вниз: красный → жёлтый → зелёный.
- Дневной цикл по умолчанию: **красный 120 с**, **жёлтый 3 с**, **зелёный 25 с**.
- Часы алгоритма — **московские (GMT+3)**, на любом телефоне. Фаза привязана к абсолютному времени и к якорю «красный включается в ЧЧ:ММ:СС по МСК», поэтому все устройства, открывшие один адрес, показывают один и тот же цвет, даже если у них разная дата в настройках или другой часовой пояс.
- Отметка цвета не нажимается случайно: на экране одна кнопка «Отметить, какой цвет вы видите», а «Красный» и «Зелёный» открываются меню снизу и закрываются сами сразу после отметки.
- Отметка уходит на сервер, локальная копия остаётся в браузере.
- ⚙ — длительности цикла и момент включения красного. Настройки одного устройства отключены: цикл у всех один, он лежит в файле на сервере. Пароля нет: сохранить цикл может любой, кто открыл страницу с Node-сервера (подробнее — в разделе «Доступ к правке»). Там же — «Настроить по нажатиям».
- ⏱ — калибровка сразу, без захода в настройки: пять светофоров на дневной цикл и пять на ночной, нажимаете лампу — рядом пишется время по МСК, и цикл считается сам.
- 📊 — статистика рассогласований и предложение по подстройке красного; там же выгрузка общей таблицы.
- 📲 — инструкция по добавлению на главный экран для iOS и Android.

## Запуск локально

```bash
node server/api.mjs                 # http://localhost:8080 — страница и приёмник вместе
```

Пароля и первого запуска-настройки больше нет: сервер сразу принимает и отметки, и правку цикла.

Для отладки без сервера: `python -m http.server 8081 --directory public` — на **другом** порту, не на 8080. Отметки копятся в локальной очереди, а расписание статика берёт из `public/config.json`. Собрать его из рабочего файла настроек: `node tools/build-config.mjs`. Без сборки страница покажет встроенные значения из кода и честно скажет, что серверного конфига нет. Правка цикла на статике намеренно недоступна: локального сохранения нет, цикл должен оставаться один на всех. На GitHub Pages тот же файл собирается workflow-ом при каждой публикации.

Если ⚙ не даёт сохранить или выгрузка не идёт, порядок проверок такой: `curl http://localhost:8080/api/health` должен ответить `{"ok":true,"timezone":"GMT+3 (МСК)",…}`. Не отвечает — Node-сервер не запущен (на Windows `node` часто не в `PATH`, тогда запускайте полным путём к `node.exe`). А если по этому адресу сидит статик-сервер (та же команда `python -m http.server`, только на 8080), страница продолжит открываться — `sw.js` держит кэш оболочки, — но `/api/*` будет отвечать 404, и панель верно скажет, что правка здесь невозможна. Проверяйте, какой процесс занял порт: `netstat -ano | findstr :8080`.

Переменные окружения сервера: `PORT` (8080), `DATA_DIR` (`server/data/observations`), `CONFIG_FILE` (`server/config/settings.json`), `STATIC_DIR` (`public`), `FEEDBACK_KEY` (ключ приёмника).

## Отметки: как собираются и где хранятся

Одна отметка = одна строка таблицы. Поля: время, id устройства, профиль (день/ночь), что горело на экране, что ответил наблюдатель, момент внутри фазы, остаток до переключения, длительность фазы, поправка часов и `shift_ms` — уже посчитанное смещение зелёного.

Путь отметки: тап по кнопке в меню → `record` в [public/js/feedback.js](public/js/feedback.js) → `POST /api/observations` на сервер → дописывание строки в `server/data/observations/YYYY-MM-DD.jsonl`. Дни в имени файла — **московские**: у файла и у цикла одна и та же полночь. Параллельно копия лежит в `localStorage` браузера (`trafficlight.observations.v1`, максимум 5000 строк) — она нужна, чтобы панель работала офлайн.

Если сервер недоступен, строка попадает в очередь `trafficlight.queue.v1` (максимум 300) и отправляется при следующем открытии страницы, при событии `online` и раз в пять минут. Дубликаты на сервере возможны при повторной отправке — у строки нет идемпотентного ключа, при выгрузке дедуплицируйте по `ts + device`.

Эндпоинты:

| метод | путь | доступ | что возвращает |
|---|---|---|---|
| POST | `/api/observations` | открыт (опционально `x-feedback-key`) | принимает одну отметку, 201 при успехе |
| GET | `/api/config` | открыт | расписание из `server/config/settings.json` — его страница показывает у всех |
| POST | `/api/config` | открыт | записывает новый цикл в `settings.json` |
| GET | `/api/summary?days=7` | открыт | сводка по всем устройствам: строки, устройства, медиана и P90 смещения. Строк с id устройств там нет |
| GET | `/api/export.csv?days=90` | открыт | вся таблица одним CSV (`;`, с BOM) — датасет для будущего обучения |
| GET | `/api/health` | открыт | `{ ok, timezone, receiverKey }` — отвечает ли сервер и включён ли ключ приёмника |

Сервер проверяет тело (не больше 8 КБ), значения полей (цвет, профиль, диапазоны времени), обрезает id устройства, ограничивает частоту (120 запросов в минуту на адрес, запись цикла и выгрузка — 20) и не пускает за пределы папки с данными. Если задан `FEEDBACK_KEY`, отметки принимаются только с заголовком `x-feedback-key`; его нужно вписать в `<meta name="feedback-key">` в [public/index.html](public/index.html).

## Ручная подстройка цикла

Расписание живёт в `server/config/settings.json` — этот файл правят по FTP, и он источник истины для всех устройств. Страница читает его при загрузке и перечитывает каждые 30 секунд, поэтому правка файла доходит до всех телефонов сама: заходить в каждый браузер не нужно. Формат файла и таблицы диапазонов — в [server/config/README.md](server/config/README.md); значение вне диапазона, битое время или неизвестный режим молча заменяется разумным, а невалидный JSON не роняет раздачу (сервер продолжает отдавать последнюю исправную версию).

Отдельных настроек на устройстве больше нет: ни переопределения цикла «для одного телефона», ни локального режима для хостинга без API. В `localStorage` остаются только поправка часов (`trafficlight.clock.v1`) и последний полученный цикл (`trafficlight.schedule.cache.v1`) — кэш, чтобы страница без сети горела по правильному расписанию. Оба сервер перезаписывает сам.

Из браузера тот же файл правится в панели ⚙ — пароля нет, вход не нужен:

1. Тап по ⚙ — сразу открывается форма с текущим серверным циклом.
2. Правка интервалов или якоря → «Сохранить на сервере» пишет `settings.json` через `POST /api/config`. Цикл меняется сразу у всех устройств; страница подхватывает чужую правку в течение 30 секунд.
3. «Исходные 120 / 3 / 25» возвращает значения по умолчанию и выключает ночной режим.

### Доступ к правке

Пароля владельца больше нет — ни на сервере, ни в странице. Это значит: **кто знает адрес сервера, тот может сохранить новый цикл и скачать таблицу отметок.** Для домашнего адреса или доверенной локальной сети этого достаточно. Если сервер выходит в интернет, закрывайте его снаружи — basic-auth или VPN перед nginx, белый список адресов, — потому что собственной авторизации у приложения теперь нет.

На статической копии (GitHub Pages, `python -m http.server`, `file://`) серверного API нет вовсе: `/api/*` отвечает 404. Расписание при этом настоящее: при публикации `server/config/settings.json` превращается в `public/config.json` тем же разбором, что и на сервере (`server/config.mjs`), и страница читает этот файл. Панель показывает значения из него и момент сборки, но править их нельзя — сохранения на статике нет, а локальная запись «только на этом телефоне» разошлась бы с общим циклом. Без собранного `config.json` панель откатывается на встроенные значения из кода и пишет об этом.

Что видно в панели настроек и статистики: откуда берётся расписание и открыта ли выгрузка. Если сервера нет, форма показана только для чтения, кнопок сохранения не видно.

Что можно настроить:

1. **Дневной цикл** — красный, жёлтый, зелёный в секундах (1–3600, жёлтый ограничен 60 с).
2. **Красный включается в, МСК** — якорь цикла, «ЧЧ:ММ:СС». Цикл непрерывен: жёлтый идёт через красный, зелёный — через красный и жёлтый, следующий красный — через всю длину цикла. Без якоря дневной цикл стартует с красного в московскую полночь, а если включён ночной режим — в момент окончания ночного окна. Ночной цикл стартует с красного в начало окна, и у него свой якорь («Красный включается в» под ночными длительностями, активен только в режиме «Отдельный цикл»). Поэтому переключение день/ночь всегда начинается с новой фазы, а не с середины чужого цикла, и окно может переходить через полночь (23:00–06:00 понимается как одно окно).
3. **Ночной режим** — чекбокс, время начала и окончания (по МСК), режим:
   - **Мигающий жёлтый** — отсчёт гаснет, жёлтая лампа мигает раз в секунду, кнопки продолжают писать отметки, но на цикл не влияют;
   - **Отдельный цикл** — свои длительности красного/жёлтого/зелёного на ночь.
4. **Исходные 120 / 3 / 25** — сброс дневного и ночного цикла, их якорей и выключение ночного режима.

Якорь определён с точностью до длины цикла: при цикле 90 с «00:00:37» и «14:32:07» — один и тот же сигнал. Страница и `derive` всегда показывают ту реплику, что ближе к последнему наблюдению, чтобы её было удобно сверять с часами.

### Настройка по нажатиям у настоящего светофора

Стоя у светофора дольше, чем длится цикл, можно не считать секунды вручную: ⏱ в верхней панели — сразу калибровка, ⚙ — настройки. Обе панели открываются сразу и без пароля; калибровка начинает считать нажатия с первого же, а на странице без Node-сервера кнопка сохранения не показывается (сохранять там некуда).

В панели пять светофоров — по одному на цикл, и переключатель **Дневной / Ночной**. У каждого профиля своя пятёрка и свои метки, поэтому за одну сессию можно снять оба цикла и сохранить их вместе.

1. Нажимайте ту лампу, которая включилась: под ней сразу появляется время нажатия по МСК. Подсвечена лампа, которую страница ждёт следующей — по ней видно, куда попадёт нажатие.
2. Один светофор = один цикл: красный, жёлтый, зелёный. После пятого зелёного один лишний красный замыкает пятый цикл — без него зелёный последнего цикла не измерен (его длительность — это время до следующего красного).
3. Выше ламп идёт строка «по циклам»: по каждому светофору красный / жёлтый / зелёный в секундах, то есть сырые измерения фаз.
4. Меню можно свернуть (✕ или тап по фону) и нажимать прямо по большому сигналу на экране — он засчитает тот цвет, который страница ждёт следующим. Во время настройки экран повторяет нажатия, а не старое расписание; сверху висит плашка «Настройка: дневной цикл, светофор 2 из 5, ждём жёлтый · 4 метки из 15».
5. «Отменить последнее» убирает промах в текущем профиле, «Начать заново» — метки обоих, «Прервать настройку» — выходит из режима, ничего не сохраняя.
6. «Закончить и сохранить» считает готовые профили и пишет их одним `POST /api/config`: дневной и ночной циклы вместе, ночные окна и якоря не трогаются.

Что считает [public/js/schedule.js](public/js/schedule.js) (`derive`): из меток собираются группы красный→жёлтый→зелёный→красный (лишняя или перепутанная метка просто не сходится в этой точке и пропускается), длительности берутся медианой по всем группам, якорь — круговой медианой моментов красного внутри длины цикла. В превью видно результат, число полных циклов, длину цикла и разброс «±N с» между включениями красного — по нему понятно, стоит ли дожимать ещё цикл. Пять светофоров дают пять измерений на цвет: медиана уже не сдвинется от одного промаха. Метки живут только в памяти страницы: они никуда не сохраняются, а сервер получает уже готовый цикл.

Сохранение из калибровки идёт через тот же `POST /api/config` с лимитом 20 запросов в минуту; отдельного разрешения на запись нет.


### Почему часы не зависят от телефона

`public/js/schedule.js` и сервер оперируют обычным epoch, а «стенные» минуты считают со сдвигом `+3 часа` (`TZ_OFFSET_MS`), без локального часового пояса и без `Date`-геттеров: Москва на летнее время не переводится, так что смещение постоянно. Точку отсчёта фазы даёт `wallMidnight` — эпоха московской полуночи.

Часы самого устройства всё же врут, а неверное время — это «не тот» цвет. Поэтому страница раз в 10 минут и при возвращении на вкладку берёт заголовок `Date` ответа сервера и хранит разницу как поправку; в подвале она подписана «часы алгоритма: GMT+3 (МСК), правка −0,8 с». Отметки пишутся уже скорректированным временем, поэтому статистика не разъезжается с расписанием.

## Как алгоритм предлагает скорректировать цикл

Ответов два, поэтому весь сигнал сводится к одному моменту — когда зелёный включается на самом деле. `shift_ms` считается в момент нажатия:

- «Зелёный» при красном или жёлтом → реальность опережает расписание на время до ближайшего зелёного (при красном добавляется ещё и весь жёлтый).
- «Красный» при зелёном → реальность отстаёт на время, которое зелёный уже горит по расписанию.

Берётся медиана смещений: она устойчива к одиночным промахам и к нажатию «на всякий случай». Предлагаемый красный = текущий минус медиана, в пределах 5–3600 с; предлагаемый якорь = текущий минус та же медиана в секундах, с остатком по суточному кругу. Предложение появляется после `MIN_SAMPLES` (3) несовпавших отметок.

Источник смещения — **сводка сервера**, если она доступна: тогда алгоритм учитывает опыт всех устройств, а не одного телефона. Без сервера считается по локальным отметкам. В панели указано, что именно использовалось. Совпавшие отметки в расчёт не идут, но видны как «Отметки совпали» — по ним видно, что модель держится.

Из той же медианы растут два взаимоисключающих предложения, и выбирает между ними человек:

- **«Красный (день): A с → B с»** — длительности не совпадают: красный короче (или длиннее) на медианное смещение. «Применить» меняет только дневной красный и уходит на сервер (ночной цикл остаётся ручным).
- **«Старт красного (день): ЧЧ:ММ:СС → ЧЧ:ММ:СС»** — длительности верны, а мимо стоит лишь фаза: якорь сдвигается на медиану (с точностью до длины цикла). «Сдвинуть» меняет только `phaseStart` дневного цикла.

Кнопки предложений есть только на серверной странице; на статической копии вместо них стоит пометка «только на серверной странице». Если смещение меньше секунды, второго предложения нет — двигать якорь некуда.

## Тесты API

Открытый API (запись цикла, выгрузка, лимиты, отсутствие пароля) проверяется скриптом [tests/api.mjs](tests/api.mjs) — без внешних зависимостей, на том же Node 18+:

```bash
node tests/api.mjs                                   # свои инстансы во временных папках
node tests/api.mjs --base http://localhost:8080      # по уже запущенному серверу
```

По умолчанию тест поднимает отдельные инстансы сервера на свободных портах, каждому даёт временные `CONFIG_FILE` и `DATA_DIR` и гасит их в конце — рабочий `server/config/settings.json` не трогается.

В GitHub Actions оба набора прогоняются на Node 18 и 22 ([.github/workflows/tests.yml](.github/workflows/tests.yml)).

| набор | что покрывает |
|---|---|
| `S` | в статике не осталось пароля: в `index.html` нет поля `type="password"`, страница не грузит `owner-key.js`, в клиенте нет `x-admin-password` и сохранения пароля, `canEdit` требует `configSource === 'server'`, service worker не упоминает удалённый файл; клиент читает `config.json` сборки, страница различает источник `file`, `sw.js` берёт конфиг из сети, `pages.yml` его собирает, сам файл не попадает в репозиторий |

## Публикация

Нужен HTTPS: без защищённого соединения браузер не даёт ни service worker, ни установку на главный экран.

**Готовый адрес (GitHub Pages).** Репозиторий публикует содержимое `public/` workflow-файлом [.github/workflows/pages.yml](.github/workflows/pages.yml): **https://nogirag.github.io/svetofor/** — это вариант 2 без Node: работает сигнал, отсчёт, ночной режим и локальные отметки, серверной таблицы и правки цикла на Pages нет. Перед выкладкой workflow собирает `public/config.json` из `server/config/settings.json`, поэтому расписание, ночное окно и длительности на странице — настоящие, из файла; чтобы их поменять, отредактируйте `settings.json`, закоммитьте и запушьте — Pages пересоберётся сам. Свой адрес получается форком репозитория с тем же workflow.

**Вариант 1 — Node на VPS или в PaaS.** Один процесс раздаёт страницу, принимает отметки и отдаёт конфиг:

```bash
cd светофор
FEEDBACK_KEY=секрет PORT=8080 node server/api.mjs
```

`FEEDBACK_KEY` необязателен и защищает только приём отметок. Пароля на сервере нет: открыты и `/api/config` (запись цикла), и `/api/export.csv`. Поэтому на публичном адресе приложение стоит закрывать снаружи — basic-auth или VPN перед nginx, белый список адресов, — иначе цикл сможет поменять любой посетитель. Расписание при этом остаётся и обычным файлом: его можно править по FTP, подробности — в [server/config/README.md](server/config/README.md).

Данные — в `server/data/observations`, папку стоит держать на постоянном диске (в контейнере — на volume). За nginx put через `pm2` или `systemd`, проксируя `/api/` на Node и отдавая статику из `public/`. Наружу из `server/` ничего отдавать нельзя: там таблица отметок.

**Вариант 2 — статический хостинг без Node.** Собрать конфиг и выложить содержимое `public/`:

```bash
node tools/build-config.mjs      # server/config/settings.json → public/config.json
```

Страница, отсчёт, ночной режим и локальная статистика работают; отметки не уходят на сервер и копятся в очереди. ⚙ и ⏱ показывают расписание из `config.json` только для чтения: серверного API нет, записывать некуда. После правки `settings.json` файл нужно пересобрать и выложить заново. Локального сохранения в браузере нет намеренно — цикл должен быть один на всех. Чтобы включить приёмник и правку цикла, вынести `/api/` на отдельный сервис с теми же эндпоинтами из таблицы.

MIME-типы, если хостинг задаёт их сам:

| расширение | тип |
|---|---|
| `.webmanifest` | `application/manifest+json` |
| `.js` | `text/javascript` |
| `.svg` | `image/svg+xml` |

После правки статики поднимайте версию в `CACHE` в [public/sw.js](public/sw.js), иначе браузеры будут держать старую оболочку.

## Известные ограничения

- Форма настроек всегда отправляет якорь явно. Пока поле не трогали, его значение — производное от ночного окна (конец окна для дня, начало для ночи), но после первого сохранения оно фиксируется: перенести ночное окно и не сдвинуть «Красный включается в» уже нельзя, правьте оба поля.
- Метки настройки по нажатиям живут только в памяти открытой страницы: перезагрузка или закрытие вкладки во время настройки теряют их (сохранённого цикла это не касается).
- Пароля нет вообще: запись цикла и выгрузка таблицы (`/api/config`, `/api/export.csv`) открыты всем, кто знает адрес сервера. Учётных записей тоже нет. Для домашнего сервера или доверенной локальной сети это приемлемо; на публичном адресе нужен внешний слой доступа (basic-auth, VPN, белый список). Лимит 20 записей в минуту защищает диск от случайного цикла запросов, но не от чужой правки.
- `/api/summary` открыт и содержит только количества и медиану, без id устройств; `/api/export.csv`, наоборот, отдаёт всю таблицу вместе с id устройств — этот адрес и держите за внешней защитой.
- HTTPS обязателен и для установки на главный экран, и для того, чтобы отметки не читались в трафике.
- У отметки нет идемпотентного ключа, повторная отправка одной и той же строки возможна.
- Приватный режим Safari не сохраняет `localStorage` между запусками: локальная копия отметок и очередь живут до закрытия вкладки, панель об этом предупреждает.
- iOS не умеет добавлять на главный экран по кнопке — только через меню «Поделиться», поэтому там лежит инструкция, а не установщик.
