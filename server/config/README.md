# Папка server/config

Здесь лежат файлы, которые правятся на сервере — по FTP или в панели хостинга.

## settings.json — расписание светофора

Это источник истины для всех телефонов: настройки одного устройства их больше нет.
Страница читает файл через `GET /api/config` при загрузке и перечитывает каждые 30 секунд,
поэтому правка доходит до всех устройств сама — заходить в каждый браузер не нужно.
В `localStorage` браузера остаётся только копия последнего полученного цикла (чтобы
офлайн не слетать на значения из кода) и поправка часов; оба сервер перезаписывает сам.

```json
{
  "day":   { "red": 120, "yellow": 3, "green": 25, "phaseStart": "00:00:00" },
  "night": {
    "enabled": false,
    "start": "23:00",
    "end": "06:00",
    "mode": "flashing",
    "cycle": { "red": 60, "yellow": 3, "green": 25, "phaseStart": "23:00:00" }
  }
}
```

| Поле | Что значит | Диапазон |
| --- | --- | --- |
| `day.red/yellow/green` | длительности дневного цикла, сек | red и green 1…3600, yellow 1…60 |
| `day.phaseStart` | момент, когда по расписанию включается красный, `ЧЧ:ММ:СС` по МСК. Можно и числом секунд от полуночи. Нет поля или битвое значение — красный стартует в конец ночного окна, а если ночи нет — в полночь | `00:00:00`–`23:59:59` |
| `night.enabled` | включать ли ночное время | `true` / `false` |
| `night.start`, `night.end` | окно в формате `ЧЧ:ММ` по московскому времени (GMT+3), независимо от часового пояса телефона; окно может переходить через полночь (`23:00`–`06:00`) | `00:00`–`23:59` |
| `night.mode` | `flashing` — дежурный мигающий жёлтый; `cycle` — отдельный ночной цикл | `flashing` / `cycle` |
| `night.cycle.*` | длительности ночного цикла, сек | как у дневного |
| `night.cycle.phaseStart` | то же для ночного цикла; по умолчанию — начало ночного окна | `00:00:00`–`23:59:59` |

Цикл непрерывен: жёлтый идёт через красный, зелёный — через красный и жёлтый, следующий
красный — через всю длину цикла. Поэтому `phaseStart` определён с точностью до длины
цикла: при цикле 90 с «00:00:37» и «14:32:07» дадут один и тот же сигнал.

Правила: значения вне диапазона, битое время или неизвестный режим молча заменяются
соседним разумным — страница не сломается. Если JSON вообще не читается (забыли
запятую), сервер продолжает отдавать последнюю исправную версию, а не пустоту.
После правки ничего обновлять не нужно: открытая страница подхватит новый цикл сама,
в пределах 30 секунд. Тот же файл перезаписывает «Настроить по нажатиям» в ⚙ — только
вместо ручной строки туда попадает цикл, посчитанный по нажатиям у настоящего светофора:
для дневного профиля это `day.*`, для ночного — `night.cycle.*`, ночное окно и его
режим остаются как были. В одной сессии можно снять оба профиля (пять светофоров на
дневной, пять на ночной) и сохранить их одним запросом: в файл попадут только те
профили, где набралось хотя бы два полных цикла.

## admin.password — пароль владельца

Одна строка — секретный пароль. Даёт право скачивать таблицу отметок
(`GET /api/export.csv`) и писать в `settings.json` (`POST /api/config`) с заголовком
`x-admin-password`. Тот же пароль человек вводит на странице в ⚙ (настройки) или ⏱
(калибровка), чтобы разблокировать правку цикла и настройку по нажатиям (дневной и
ночной профили сохраняются вместе); после первого ввода пароль остаётся в этом
браузере, и следующая правка открывается без него.

Создайте файл и напишите в него случайную строку:

```
openssl rand -hex 16 > server/config/admin.password
```

Требование к символу одно: пароль уходит в HTTP-заголовок, а заголовки живут в Latin-1.
Подойдут латинские буквы, цифры и знаки препинания без пробелов — кириллица или пробел
не уйдут, и страница заранее об этом скажет. `openssl rand -hex` этому правилу
соответствует.

Можно не хранить пароль в открытом виде, а записать его свёрток:

```
node -e "console.log('sha256:' + require('crypto').createHash('sha256').update(process.argv[1]).digest('hex'))" 'мой-пароль' \
  > server/config/admin.password
```

Сервер увидит префикс `sha256:` и будет сравнивать хеш от введённого пароля. Вводить на
странице всё равно нужно сам пароль.

Так сейчас и устроено: `admin.password` содержит свёрток, а сам пароль хранится у владельца
и на сервере его нет — скачав файл, пароль не восстановить.

Можно передать пароль переменной окружения `ADMIN_PASSWORD` — она важнее файла.
Если пароль не задан ничем, выгрузка и запись конфига закрыты (ответ `503`), а страница
показывает, что доступ блокирован на сервере: тогда остаётся только править
`settings.json` по FTP.

Файл не должен попасть в git — он в `.gitignore`.

## Если хостинг отдаёт всё дерево подряд

`server/` вне корня раздачи (`public/`) — при правильной настройке файлы отсюда в веб
недоступны. На дешевом хостинге, где в веб-корень кладут весь проект целиком,
`admin.password` скачается обычным запросом. Поэтому в файле лежит свёрток, а не пароль:
скачав его, доступ получить нельзя — подобрать пароль по хешу здесь нечем. Сам пароль всё
равно держите в секрете, а если он когда-то лежал в файле открытой строкой — замените его
и способ хранения.
